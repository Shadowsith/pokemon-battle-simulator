# Checklist: move animation review (Gen 1–6)

**Goal:** watch the current animation of every move once and tick it off when it looks right. 621 moves in total.

## How the animations work
`MoveAnimationService.buildVisual()` in [move-animation.service.ts](../src/app/core/services/move-animation.service.ts) derives each animation from the move's @pkmn/sim data. Nothing is hand-made per move. The **style** column below is the delivery the code currently picks:

| Style | Look | Moves |
|---|---|---|
| `melee` | caster lunges and hits the target | 173 |
| `projectile` | particle stream flies to the target | 133 |
| `lob` | orb flies in an arc | 20 |
| `beam` | straight beam from caster to target | 17 |
| `pulse` | rings travel to the target | 5 |
| `sonic` | sound waves | 11 |
| `field` | hits the whole target side | 36 |
| `powder` | powder cloud drifts onto the target | 5 |
| `selfAura` | aura around the caster (buffs, heals) | 121 |
| `targetAura` | aura around the target (status moves) | 96 |
| `weather` | screen-wide weather effect | 4 |

**Rule:** a Pokémon sprite never turns around or spins on its own axis (that never happens in the Pokémon games and looks odd). It always keeps facing its opponent; a "circling" movement moves the sprite along a path instead.

Type sets the colour and particle shape. Base power sets the size. Multi-hit, priority, two-turn, drain and recoil add extra motion.

## Priority
⭐ = review first. Marked are:
- every attack with **70+ base power**,
- common tournament **status moves** (setup, hazards, recovery, protection, status, screens, weather, support),
- a few common attacks with **variable power** (Low Kick, Grass Knot, Gyro Ball, Heavy Slam, Heat Crash, Seismic Toss, Night Shade, Super Fang).

Search for `⭐` to jump between them. 284 moves are marked.

## Review notes
- Use the Debug-Kampf (debug mode) to try moves quickly.
- If a move looks wrong, add a short note after the entry, e.g. `— ❌ should be a beam, not a lob`.
- **Reviewed** = watched at least once, as attacker on both sides.

## When a new custom animation is added
Every move has a self-made free sound (`public/assets/sounds/moves/free/<id>.mp3`). Its recipe in `scripts/move-sounds/recipes/<type>.mjs` (Normal: `recipes/normal/`) is timed to the animation the move had when the sound was made. **Only when a move gets a new hand-made animation** (an entry in a `moves/<type>-moves.ts` registry, including a custom charge turn), check that move's free sound again:
- [ ] Compare the free sound with the original clip (`public/assets/sounds/moves/<id>.mp3`) and with the new animation: does it still fit?
- [ ] If not, re-time the recipe to the new animation: impact moments, number of hits, length (animation length plus a short tail). Note the new timeline in the recipe's comment.
- [ ] Remove fleck jingles (`statUp`, `burn`, `flinch`, …) that the new animation no longer shows. Custom animations don't play the generic fleck unless they call `FxEffects.afterImpact`.
- [ ] Regenerate with `node scripts/synth-move-sounds.mjs <id>` and listen to it in the Debug-Kampf.

Changes to the generic delivery animations or to this review list alone don't need a sound check.
